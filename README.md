# 班级宠物养成（v15 · 可部署版）

面向初中班级的习惯养成与学习过程工具：例外式全班基础达标、周目标打钩与周五复盘、错题重测、小队互助、集体奖励、虚拟宠物养成。**无公开排名、无羞辱面、学生免费。**

v15 起为**前后端一体的单校私有化系统**：Node + Express + SQLite 服务端持有唯一账本，前端为 React 瘦客户端。数据不出校。

```bash
npm ci
npm run build        # 类型检查（前端 + 服务端）+ 构建
npm run start        # 生产启动：http://localhost:3050（PORT 可覆盖）
npm run dev          # 开发：服务端(3050) + 前端热更新(5173/5174)
npm run seed:demo    # 演示数据（教师/学生账号打印到控制台）
npm run admin -- list# 运维 CLI：班级/教师/密码/备份
npm test             # 25 个单元测试（规则层 + 引擎权限与红线不变量）
```

部署（校内服务器、HTTPS、备份、升级）见 `DEPLOY.md`；隐私告知与监护人同意书模板见 `PRIVACY.md`。

## 架构

```
src/types.ts src/rules.ts        共享：数据模型 + 纯规则（进度公式/抽样/想念暂停/重测调度）
src/engine/                      共享：领域引擎（全部业务变更 = 纯函数，actor 由服务端注入）
server/                          服务端：SQLite 持久化、账号会话、action 通道、角色视图裁剪、
                                 追加式事件日志、每日备份、admin CLI
src/store.ts src/api.ts          客户端：视图缓存 + 动作转发（8s 轮询保持课堂多端同步）
src/pages/                       页面：登录/安装向导、宠物主页、申报、大屏、抽查、目标、周报、花名册…
```

同一套引擎在服务端执行与校验、在客户端做只读选择器——规则只写一遍。

## 角色与职责

| 角色 | 登录方式 | 职责 | 看不到什么 |
| --- | --- | --- | --- |
| 管理员 | 用户名+密码 | 维护教师账号（创建/重置密码/分配班级/停用）、班级、**激励规则**、校名 | 任何学生过程数据（最小权限） |
| 班主任 | 用户名+密码 | 课堂大屏、抽查、目标、周报、花名册（学生账号/PIN/同意书） | 其他班数据 |
| 任课教师 | 用户名+密码 | 所任教班级的大屏与抽查 | 个人目标编辑、花名册 |
| 学生 | 班级+姓名+PIN | 自己的宠物、申报、目标、复盘 | 他人流水/心情/习惯明细，任何排名 |

**激励规则可配置**（管理台「激励规则」页，全校即时生效、留审计日志）：各类申报分值、每日入账/消耗/申报/互评上限、抽查队列范围、荣誉席位与连庄上限、小队档位阈值与连携加分、宠物成长节奏、集体奖励阈值、错题重测间隔、证据字数底线。服务端做边界校验（如 铜<银<金、日上限 2–30）。
**不可配置（产品宪法）**：不设任何公开排名与垫底名单；「未完成/豁免」只进教师端；学生心情永不影响宠物与奖励；积分不可转让、学生零付费。

## 上线四门槛的落地方式

1. **真实账号**：管理员/教师用户名+密码、学生班级+姓名+PIN（bcrypt 存储、httpOnly 会话、登录限速 5 次/15 分钟、CSRF 校验）。首次运行进入安装向导创建管理员；教师账号由管理员在管理台维护；学生 PIN 由班主任在花名册生成/重置。
2. **服务端账本**：localStorage 仅剩 UI 偏好。所有变更经 `/api/action` 由引擎校验后落库，并写入追加式 `events` 审计日志（时间/操作者/动作/参数/成败）；每日自动备份，保留 30 份。
3. **未成年人合规**：监护人同意书未登记的学生无法登录（服务端强制）；同意登记留痕（谁、何时、何种方式）；「删除学生」一键清除账号与全部养成数据（删除权）；隐私文本见 `PRIVACY.md`。
4. **多班支持**：一校多班，任课教师可跨班切换；班级、教师由安装向导 + admin CLI 管理。

## 隐私：从 UI 约定变成服务端保证

学生视图由服务端裁剪后下发——学生**拿不到**：他人积分流水、他人心情、他人「未完成/豁免」明细、他人申报与周期历史、名册元数据；互评池已剥离申报者身份。教师视图含全班过程数据与「本周活跃学生数」等运营指标。

## 机制要点（v14 重构保留）

- **公屏无负面**：投影大屏只显示正向事件与班级聚合；「未完成/豁免」仅教师端与周报可见。
- **报雨无代价**：心情签到只进班主任关怀清单（连续 2 天雨提示课后聊聊），绝不影响宠物或奖励。
- **班级周进度**：按全周（周一至周五）计算，豁免不进分母；周一全员达标只有 20%，集体奖励自然落在周四五。
- **OKR 完整周期**：周目标 + 证据打钩（同学/老师确认）+ 周五自评复盘 + 历史归档；奖励挂「完成复盘循环」而非达成率；跨周待确认转教师补确认，不蒸发。
- **错题重测**：订正入账 3 天后自动提示再测（检索练习 + 间隔效应），通往成绩的最短路径。
- **反刷设计**：日入账/申报/互评上限、抽查存疑优先 + 按日随机抽样、积分不可转让、稀有装扮仅成就解锁。
- 想念值只在工作日累积（周末假期暂停）；照料全部免费；宠物永不病死。

## 已知边界（如实告知）

- 单校单实例；区级只读、跨校租户为规划项
- 无邮箱/短信找回（校内场景：admin CLI 与花名册重置）
- 家长角色未实现（同意书线下签署、班主任登记）
- 课堂大屏多端并发依赖 8 秒轮询，未用 WebSocket
